# LeRobot 数据采集说明

## 当前采集链路

```text
Pico 手柄
  -> TeleopXR
  -> PyRoki IK
  -> LeRobot action 转换/限位
  -> 安全 CAN 输出
  -> 收集同一控制周期的 16 路实际电机反馈
  -> 独立写盘线程保存 observation + 最终实际下发 action
```

数据使用 LeRobot 原生 `LeRobotDataset` 格式。

## 每帧内容

当前数据结构包含：

- `observation.state`：左右双臂和夹爪的实际电机回传；
- `action`：经过本项目限位后最终实际下发的 16 路位置目标；
- `observation.images.*`：预留字段，当前尚未配置相机；
- `task`：本次任务的自然语言描述；
- LeRobot 自动生成的时间戳、帧号和 episode 编号。

原始 IK 只负责产生控制目标，不直接作为训练 action。经过单位转换、限位和
本项目速度、加速度和关节限位处理后的最终值才会写入 `action`。

## 时间同步顺序

控制和采集按以下顺序处理一帧：

1. 下发经过限位的经典 8 字节 CAN 动作帧；
2. 收集这一轮动作产生的左右各 8 路实际反馈；
3. 只有本轮 `16/16` 反馈完整时才生成 observation，绝不拿旧缓存补帧；
4. 将 observation 和最终实际下发 action 放入有界写盘队列；
5. 独立线程按配置的 FPS 写入当前 episode。

CAN 输出不在 PyRoki IK 线程执行，磁盘写入也不在 CAN 输出线程执行。

## Episode 规则

当前规则简单明确：

- 启动一次采集进程，建立一个新的时间戳目录；
- 进程运行期间、双侧握键使能时的数据属于一个 episode；
- 手柄静止但仍保持使能时继续采集反馈和保持动作；
- 松开任意侧握键时暂停采集，重新使能后继续当前 episode；
- 按 `Ctrl+C` 正常退出时保存 episode 并 finalize；
- 没有采到任何帧时不会生成空 episode；
- 数据写入异常时丢弃当前未完成 episode，不让磁盘异常阻塞 IK。

默认保存位置：

```text
Openarm_lerobot/data/YYYYMMDD_HHMMSS/
```

`data/` 已加入 `.gitignore`，采集数据不会进入 Git。

## 真机采集入口

```bash
cd /mnt/data/清敏感知/Openarm/Openarm_lerobot
./scripts/start.sh record \
  --dataset-task "填写当前任务，例如：拿起桌面的水杯"
```

该命令会连接 `can0/can1` 并使能电机。当前不要执行，必须先完成：

1. Pico 离线 IK 验证；
2. 关节方向、零点和限位核对；
3. 低速控制验证；
4. 急停、超时和失联保护验证。

## 可调参数

默认采集频率为 20 FPS，与当前双臂反馈循环可持续频率一致：

```bash
./scripts/start.sh record --dataset-fps 20
```

修改数据集元数据 ID：

```bash
./scripts/start.sh record --dataset-repo-id local/openarm_pick_cup
```

修改保存根目录：

```bash
./scripts/start.sh record --dataset-root /mnt/data/openarm_datasets
```

## 相机状态

当前项目尚未把相机接入 LeRobot 机器人配置，因此现阶段数据集中没有
`observation.images.*`。接入相机时还需要实现相机 latest-frame 缓存和时间
对齐，不能在 CAN 输出线程中同步等待相机。

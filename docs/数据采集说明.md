# LeRobot 数据采集说明

## 最终采集链路

```text
Pico 手柄
  -> TeleopXR
  -> PyRoki IK
  -> LeRobot action 转换、限位与平滑控制
  -> 安全 CAN 输出
  -> 双臂和夹爪实际电机反馈

普通 USB 相机 1/2 -> 后台 latest-frame 缓存 ┐
Aurora930 ROS RGB/Depth -> 后台缓存          ├-> 15 FPS 同步数据帧
电机反馈 + 最终下发 action                  ┘
  -> LeRobotDataset 独立写盘线程
```

相机读取、ROS 回调和视频写盘都不在 CAN 输出线程中执行。每个数据帧只复制
四路已经到达的最新图像；任一图像超过 1 秒没有新帧时，数据集写入会停止，
但不会用旧图像冒充新图像，也不会阻塞机械臂的安全控制。

## 每帧字段

- `observation.state`：左右双臂与夹爪的 16 路实际电机反馈；
- `action`：经过单位转换、关节限位、速度/加速度限制后最终实际下发的
  16 路位置目标；
- `observation.images.scene`：普通外接 USB 相机 1 RGB，`640×480`；
- `observation.images.scene_secondary`：普通外接 USB 相机 2 RGB，
  `640×480`；
- `observation.images.aurora_rgb`：Aurora930 RGB，`480×300`；
- `observation.images.aurora_depth`：Aurora930 单通道深度，`480×300`；
- `task`：本次任务的自然语言描述；
- LeRobot 自动生成的时间戳、帧号和 episode 编号。

RGB 使用 LeRobot 的 AV1 视频格式。深度使用 LeRobot 的 12 位 HEVC 深度格式，
数据集读取器默认返回毫米值。Aurora 原始标定参数、物理设备路径和深度单位说明
保存在每次数据集的：

```text
meta/openarm_cameras.json
```

点云不重复写盘；需要时可由深度图与标定参数重建。

## 相机与同步约定

- 两台普通相机序列号相同，脚本按 USB `0c45:636b` 自动查找两条不同的
  `/dev/v4l/by-path/` 路径，不使用可能随重启变化的 `/dev/videoN`；
- Aurora930 通过 `/aurora/rgb/image_raw` 和
  `/aurora/depth/image_raw` 读取；
- Aurora 为 15 FPS，因此最终数据集默认也是 15 FPS；
- 每个控制采样点使用当时最近的四路完整图像；
- 只在 Pico 双侧握进入控制状态时写入数据；
- 松开任意侧握时机械臂保持当前位置，同时暂停数据写入；
- 再次双侧握后继续当前 episode。

## 最终运行入口

确认机械臂周围无人、急停/断电手段可用、Pico 与电脑连接同一局域网后运行：

```bash
cd /mnt/data/清敏感知/Openarm/Openarm_lerobot
./scripts/record.sh \
  --num-episodes 20 \
  --dataset-task "拿起桌面的水杯"
```

这个脚本会一次完成：

1. 检查两台普通 USB 相机和 Aurora930；
2. 默认在局域网监听 TeleopXR，并输出 Pico 应打开的网址；
3. 只读检查已由用户提前配置好的 `can0/can1`，不会执行 sudo 或初始化电机；
4. 启动 Aurora930 ROS 驱动；
5. 启动 Pico、IK、真机控制和 LeRobot 数据记录；
6. 在本机打开四路 2×2 实时预览窗口；
7. 退出时关闭相机驱动并保存当前 episode。

默认是局域网模式，不需要连接 Pico USB。`--num-episodes` 表示本次运行
需要成功保存的 episode 数量；达到数量后程序自动保存并退出。若临时改回
USB 有线模式：

```bash
./scripts/record.sh --pico-link usb \
  --num-episodes 20 \
  --dataset-task "拿起桌面的水杯"
```

USB 模式会检查 ADB 授权并建立 `localhost:4443` 反向端口，退出时自动删除。

运行时不要关闭预览窗口。结束采集时回到启动终端按一次 `Ctrl+C`，等待
LeRobot 完成视频编码和数据集 finalize 后再断电。

默认保存位置：

```text
Openarm_lerobot/data/local_openarm_vr/
```

数据集名称由 `--dataset-repo-id` 决定，其中 `/` 在本地目录名中转换成
`_`。例如 `local/openarm_pick_cup` 保存到
`data/local_openarm_pick_cup/`。再次用相同名称启动，会继续追加 episode，
不会覆盖已有数据。`data/` 已加入 `.gitignore`，不会提交到 Git。

## 常用参数

修改数据集元数据 ID：

```bash
./scripts/record.sh \
  --num-episodes 20 \
  --dataset-repo-id local/openarm_pick_cup \
  --dataset-task "拿起桌面的水杯"
```

修改保存根目录：

```bash
./scripts/record.sh \
  --num-episodes 20 \
  --dataset-root /mnt/data/openarm_datasets \
  --dataset-task "拿起桌面的水杯"
```

临时指定另一台普通相机：

```bash
OPENARM_SCENE_CAMERA=/dev/video4 ./scripts/record.sh \
  --num-episodes 20 \
  --dataset-task "拿起桌面的水杯"
```

只有确实不需要本机预览时，才可添加：

```bash
--no-camera-preview
```

## Episode 规则

- 一个 `dataset-repo-id` 对应一个长期使用的数据集目录；
- 初始为等待状态，双侧握只负责机械臂控制，不会自动写数据；
- 按右手柄 `A` 开始当前 episode，之后仅在双侧握控制时写有效帧；
- 按右手柄 `B` 放弃当前 episode 并回到等待状态；
- 按左手柄 `X` 保存当前 episode 并回到等待状态；
- 达到 `--num-episodes` 指定的本次保存数量后自动结束程序；
- 按 `Ctrl+C` 正常退出时保存尚未结束的最后一个 episode，并 finalize
  整个数据集；
- 下次用相同 `dataset-repo-id` 启动时，从已有 episode 编号继续追加；
- 没有有效控制帧时不生成空 episode；
- 相机或磁盘写入异常时丢弃未完成 episode，不让写盘异常阻塞 CAN 控制。
